# 《从零构建 Agent Harness 智能体应用开发实践》目录

稳定文件名即拼装顺序。目录按读者的问题链排列：先看失控，再写约束，接着保存状态、运行、验收和落地。正文必须按此标题写作，不得另起一套目录。

| 顺序 | 文件 | 标题 | 读者读完应能做什么 |
| --- | --- | --- | --- |
| 00 | `00-preface.md` | 前言：为什么 Agent 需要 Harness | 判断自己是不是这本书的读者，并按「先原则后命令」的顺序读下去 |
| 01 | `01-agent-out-of-control.md` | 第 1 章 智能体为什么会失控 | 用一条因果链描述自己项目里的返工，而不是抱怨「模型不够聪明」 |
| 03 | `03-four-principles.md` | 第 3 章 四条原则：显式假设、最小实现、边界清晰、验证优先 | 在动手前写出假设、非目标、boundary 和 verify |
| 04 | `04-task-package.md` | 第 4 章 任务包：范围、任务、验收的同一真源 | 为一次跨会话工作建立三件套，并解释为什么不能只写待办清单 |
| 05 | `05-single-loop.md` | 第 5 章 单线闭环：从一句话目标到可恢复执行 | 走完 goal/new → run → check → done 的最小闭环，中断后能接上 |
| 06 | `06-machine-gates.md` | 第 6 章 机器门禁：不要相信「看起来完成」 | 用退出码和证据关闭问题，而不是用口头通过代替验收 |
| 07 | `07-git-landing.md` | 第 7 章 Git 收尾：干净工作树、独立分支、提交与发布分离 | 把一次复杂工作安全落到 Git，而不把无关改动带进发布 |
| A | `a-command-map.md` | 附录 A 命令与阶段对照 | 需要查命令时能对上阶段，但不把附录当正文 |
| B | `b-artifact-map.md` | 附录 B 制品与目录地图 | 打开一个 `.spec` 目录时知道每个文件的职责 |
| C | `c-failure-modes.md` | 附录 C 失败模式速查 | 对上自己正在踩的坑，并找到对应章节 |

贯穿案例：用 Spec 工作流写这本书本身。读者会在各章看到同一条工作如何被范围约束、任务拆开、门禁拦住、再收进 Git。
