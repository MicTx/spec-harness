# 术语表

本书术语约定；不主张这是行业唯一的 Harness 定义。

| 术语 | 含义 |
| --- | --- |
| Agent | 能调用工具、读写文件、执行命令的智能体，不是只聊天的模型窗口 |
| Harness | 包围 Agent 的运行与约束机制；本书聚焦范围、任务、验证和交付的控制平面子集 |
| 控制平面 | 决定「做什么、做到哪、怎样算完」的层；不负责写出每一行业务代码 |
| 执行平面 | 真正改代码、跑测试、开浏览器的运行时，可替换 |
| 验证层 | 用可重复命令、测试或构建证明完成；口头「通过」不算 |
| 交付层 | 归档、提交、合并、发布；验证未过不能进入 |
| 任务包 / Development Record | `.spec/specs/YYYY-MM-DD_slug/` 下的一次开发闭环 |
| 三件套 | `spec.md`（范围）、`tasks.md`（执行）、`checklist.md`（验收） |
| boundary | 本任务允许改动的文件或模块边界 |
| verify | 本任务怎样证明完成的具体命令或观察 |
| 门禁 | 以脚本退出码为真源的检查，不能用旧输出或记忆替代 |
| 单线闭环 | 一个人、一个任务包、一条 integration branch 走完规划到收尾 |
| 主线程 | 对共享边界、合流、最终验收负责的会话 |
| N=1 | 无法安全拆分时由主线程接管，留下可审计记录 |
| 畅销电子书（本轮） | 有读者承诺、问题驱动目录、贯穿案例、练习与反模式，可导出 EPUB；不是销量承诺 |
