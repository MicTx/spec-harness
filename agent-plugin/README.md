# agent-plugin/ — Agent Plugin Manifest Templates

This directory addresses a release question: how to package agent plugin manifest metadata without including the source repository's maintenance files in the user package. The packaging script consumes these templates; field names and placeholders must remain parseable.

> Entry classification: **maintainer-only**. This directory exists only in the source repository and is excluded from the runtime export tree. See the public entry indexes at [`../docs/README.md`](../docs/README.md) and [`../docs/README-en.md`](../docs/README-en.md).

These are packaging templates for `.maintainer/tools/release/package_agent_plugin.py`. The script reads the manifest templates, renders placeholders, validates fields, and assembles this repository's runtime skill payload into a distributable plugin zip.

Formats follow the Agent Plugins 1.0 and Claude Code plugin manifest specifications:

| Template | Target format | Manifest location in output |
|---|---|---|
| `plugin.json.template` | Agent Plugins 1.0 (primary, default) | `plugin.json` at the plugin root |
| `claude-plugin.json.template` | Claude Code plugin | `.claude-plugin/plugin.json` |
| `dsh-package.json.template` + `dsh-cordis.patch.yml.template` + `dsh-index.js.template` | DeepSeek Harness (dsh) bundle | `package.json` (`dsh.bundle.patch`), `cordis.patch.yml`, and `index.js` at the plugin root |

## Placeholders

| Placeholder | Meaning | Default source |
|---|---|---|
| `{{NAME}}` | Plugin name | Constant `spec-harness`. Agent Plugins requires 1–64 characters, only `a-z0-9-.`, alphanumeric first and last characters, and no `--` or `..`; Claude Code requires kebab-case. |
| `{{VERSION}}` | Plugin version | `version` in the repository's `pyproject.toml` |
| `{{DESCRIPTION}}` | Short description | `description` in `pyproject.toml` |
| `{{DISPLAY_NAME}}` | Human-readable name (Claude Code format only) | Constant `Spec Harness` |
| `{{HOMEPAGE}}` / `{{REPOSITORY}}` | Homepage / repository URL | Defaults to `https://github.com/MicTx/spec-harness`; an explicitly empty value removes the field from the manifest. |
| `{{LICENSE}}` | SPDX identifier | Constant `PolyForm-Noncommercial-1.0.0` |
| `{{KEYWORDS}}` | Search tags (JSON array literal) | Constant `["spec", "task-package", "workflow", "agent-skills"]` |

## Build commands

```bash
# Default: Agent Plugins 1.0 format, producing dist/<name>-<version>-agent-plugins.zip
python3 .maintainer/tools/release/package_agent_plugin.py

# Claude Code format
python3 .maintainer/tools/release/package_agent_plugin.py --format claude-code

# dsh bundle format (after extraction: `dsh plugin --profile <name> add ./spec-harness`)
python3 .maintainer/tools/release/package_agent_plugin.py --format dsh

# Custom output and metadata
python3 .maintainer/tools/release/package_agent_plugin.py --name spec-harness --version 1.2.3 \
    --output dist/spec-harness.zip --force
```

## Output layout (agent-plugins format)

```text
<name>/
├── plugin.json            # Rendered from plugin.json.template and validated
├── README.md              # Installation instructions generated by the script
├── LICENSE
└── skills/
    └── spec/              # Runtime skill payload under the compatibility name (SKILL.md is at the skill root)
        ├── SKILL.md
        ├── install.sh
        ├── agents/ references/ scripts/ ...
        ├── commands/            # Claude Code adds spec/new, spec/go, spec/done
        └── hooks/hooks.json     # generated only for hook-capable plugin hosts
```

The Claude Code format adds the manifest at `.claude-plugin/plugin.json` and generates `commands/spec/{new,go,done}.md` plus the Stop hook manifest. Hookless formats omit those host-specific files; the skills payload stays identical.

## Notes

- The two manifest schemas differ: Agent Plugins has **closed** top-level fields (do not add fields to the template; client-specific data belongs under `extensions`); Claude Code has open top-level fields (unknown fields are ignored).
- Templates must remain valid JSON apart from placeholders. After rendering, the script rejects any remaining `{{...}}`.
- In dsh format, `index.js` is a dependency-free Cordis plugin (`inject=['skills']`) that registers the `bundled` provider (rank 600) on `ctx.skills` and strips frontmatter; `package.json` declares `dsh.bundle.patch`. The format follows dsh `docs/user/develop/basic/publish.md` and `packages/experimental/skill-badge`. dsh is a developer preview and has not been live-validated.
