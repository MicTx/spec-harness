# Git Ownership

Slugs use `YYYY-MM-DD_verb-object`. One active package binds one non-protected branch recorded in `Binding`; harness creates `spec/<slug>` only when planning starts on a protected branch. `plan-go` freezes the package once; neither execution commands nor a second Go may run on another branch.

Each successful task verify may create `wip(<slug>): <task title>` with the footer `Spec: <slug>`. Delivery archives the package and creates the final package commit. V4 `commit` stops there; `merge` returns to main; `push` additionally pushes after the delivery gate passes, removes the delivery branch's linked worktrees, then deletes the branch. `/spec:push` runs after archive from the bound delivery worktree and performs the same merge, push, worktree cleanup, and branch deletion. A dirty linked worktree is kept and reported as a cleanup warning instead of force-removed.

For V4 `merge`/`push`, `done` runs `push.preflight` before archiving. It resolves a unique worktree for the bound delivery branch and a unique worktree for the resolved main branch, rejects duplicate bindings, rejects a dirty target worktree, validates the remote, and predicts whether the delivery commit will leave uncommitted changes. Any violation is reported before archive so the package stays retryable. If no worktree is bound to main, delivery checks out main in the bound delivery worktree.

`deliver` runs the same deterministic checks as `preflight`, then performs checkout → merge → push in the resolved target worktree inside one recoverable step. A failed merge aborts without moving the bound delivery worktree; a failed push keeps the merge commit on the target branch and leaves the delivery worktree on its spec branch, so the command can simply be retried. A completed merge makes a retry report "Already up to date" and continue from the failed step.

Never bypass hooks, overwrite user changes, reset, or stash to satisfy a gate. While a package is active or archived on the current branch, the session hook rejects direct Git commit/push tools so state transitions stay harness-owned. `--no-verify`, commit's `-n`, common shell wrappers, and explicit `core.hooksPath` overrides are rejected; this is a host policy gate, not an OS sandbox. A dirty baseline is recorded for boundary attribution; pre-Go changes inside a task boundary are committed with the delivery, while new changes outside task boundaries fail delivery.
